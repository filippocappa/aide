# Aide — Project Spec

Personal AI assistant that manages your schedule, reminders and mail through chat (Discord first, Swift iOS app second), running 24/7 on your own Ubuntu desktop.

## 1. Goals

- Talk to the assistant in natural language: "fix my calendar", "remind me to call X tomorrow at 5", "what's in my inbox".
- The assistant acts on real data (calendar, reminders, mail) and confirms what it did.
- Always on, survives restarts and power loss with no data loss.
- Reachable from anywhere without opening ports to the internet.

Non-goals (for now): iMessage, a Mac helper, App Store distribution, multi-user support.

## 2. Architecture

```
 Discord  ─┐
 Telegram ─┼─► Channel adapters ─► Agent core (Claude + tools) ─► Tools ─► Google Calendar API
 iOS app  ─┘   (long polling /      │                                  ├─► Mail (IMAP / Gmail API)
   (HTTPS      HTTPS API)           │                                  └─► Reminders store
    over                            ▼
  Tailscale)                    SQLite (WAL)  ◄── Scheduler (reminders, digests)
```

- **Channel adapters** are thin. They turn an incoming message into `(user, text)` and send replies. The core knows nothing about Discord or iOS.
- **Agent core** runs the Claude tool-use loop and holds conversation history.
- **Tools** are the only code that touches external services.
- **Scheduler** fires reminders and the weekly digest, and pushes them out through Discord.

## 3. Stack

| Layer | Choice |
|---|---|
| Backend | Python 3.12, FastAPI, `discord.py` (outbound gateway connection) |
| LLM | Anthropic API: Haiku 5.5 (`claude-haiku-5-5`) for simple requests, Sonnet 5.5 (`claude-sonnet-5-5`) default, Opus 5.5 (`claude-opus-5-5`) for rare hard cases |
| Storage | SQLite in WAL mode, on disk |
| Scheduler | APScheduler with a SQLite job store |
| Calendar | Google Calendar API (OAuth), server-side |
| Mail | Gmail API (OAuth), several accounts; IMAP with an app-specific password if an iCloud account is added later |
| Reminders | Own table in SQLite is the source of truth; mirrored to Apple Reminders by the iOS app |
| iOS app | Swift / SwiftUI, EventKit |
| Network | Tailscale, always on (see section 5) |
| Process manager | systemd |

## 4. Features

### 4.1 Calendar
- List, search, create, move and delete events on Google Calendar.
- "Fix my calendar": detect conflicts and propose a rearrangement, then apply it only after confirmation.
- Works immediately, because the server talks to Google directly.

### 4.2 Reminders
- The server stores reminders and fires them through Discord at the due time. This is the reliable path.
- The iOS app reads and writes Apple Reminders through EventKit and syncs with the server whenever it is opened.
- A reminder created in chat appears in Apple Reminders at the next app sync, and a reminder created in Apple Reminders reaches the server at the same point.

### 4.3 Mail
- Phase 1 is read-only: list, search and summarise.
- Phase 2 adds drafts. Sending, deleting and forwarding always need explicit confirmation in chat.
- Mail.app cannot be read from iOS, so the backend connects to the mail provider directly.

### 4.4 Notifications
- On-demand and time-critical alerts go through Discord DMs (Telegram later, via a second adapter).
- The weekly digest is generated by the server. The app can also schedule a local notification (for example Sundays at 9:00) that opens the app and syncs.

### 4.5 iOS app
- Chat UI against the backend API.
- Dashboard: today's events and reminders.
- EventKit sync for Reminders (and Calendar reads).
- Limits with a free Apple ID: the build expires every 7 days, there is no remote push, and it syncs only while open. Discord covers push.

### 4.6 Habits and identity (Atomic Habits protocols)
The assistant helps you become who you want to be, not only manage tasks.

- **Identity first.** You define target identities ("I am someone who trains every day"). Every habit is linked to one, and the assistant refers back to it.
- **Implementation intentions.** Each habit is stored as "I will [behavior] at [time] in [place]" and scheduled as a calendar block plus a reminder.
- **Habit stacking.** A habit can be anchored to an existing one ("after my morning coffee, I will…") and reminded at that anchor.
- **Two-minute rule.** For a habit you keep missing, the assistant proposes a two-minute starter version.
- **Make it obvious / easy / satisfying.** Cues and reminders for the first, friction removal for the second (pre-scheduled time, prepared steps), and a visible streak and daily check-in for the third.
- **Never miss twice.** After one missed day the assistant nudges you the next day, with no guilt framing.
- **Daily check-in.** One short chat prompt in the evening: did you do it, yes or no.
- **Weekly review.** Part of the weekly digest: completion rate per habit, what blocked you, and one adjustment to try.
- **Environment design.** When a habit keeps failing, the assistant asks what in your schedule or surroundings is in the way and proposes a change.

## 5. Hosting and reliability (Ubuntu desktop)

- **Always on.** The backend runs as a `systemd` service: `Restart=always`, `After=network-online.target`, enabled at boot.
- **Persistence.** All state lives on disk: SQLite (WAL) for conversations, reminders, tokens, sync state and scheduler jobs. Nothing important is kept only in memory. After a restart the scheduler reloads its jobs, and any reminder that came due while the machine was down is sent right away with a "late" note.
- **Backups.** A nightly `sqlite3 .backup` copy of the database to a second location, keeping the last 14.
- **Remote access.** Tailscale is installed on the Ubuntu desktop and always on: `tailscaled` is enabled at boot and the machine's node key does not expire (key expiry disabled in the admin console). The iOS app and any admin access (SSH included) go through the tailnet, so no ports are opened to the internet. Discord needs no inbound connection because the bot holds an outbound gateway connection.
- **Wake relay.** The existing relay powers the desktop back on if it goes down. Boot-time systemd start brings the service back automatically, so no manual step is needed after a wake.
- **Power loss.** SQLite WAL with `synchronous=NORMAL` or higher keeps the database consistent after an unclean shutdown.
- **Logs.** Structured logs to the journal (`journalctl -u aide`), plus a Discord DM to you when the service starts, crashes repeatedly, or a tool fails.

## 6. Security

- Only your Discord user ID is allowed. Every other sender is ignored.
- Secrets (Anthropic key, Discord bot token, Google and mail credentials) live in an env file readable only by the service user, never in the repo.
- Treat all calendar, mail and web text as untrusted input (prompt injection). Tool output is data, not instructions.
- Destructive or outward-facing actions (send, delete, forward, bulk calendar changes) require a confirmation step in chat.
- The iOS API requires a bearer token and is reachable only over Tailscale.

## 7. Data model (SQLite)

- `messages(id, channel, role, content, ts)`: conversation history
- `reminders(id, title, due_at, status, apple_id, updated_at)`
- `oauth_tokens(provider, access, refresh, expires_at)`: encrypted
- `sync_state(source, cursor, last_sync_at)`
- `identities(id, statement)`
- `habits(id, identity_id, behavior, time, place, anchor, min_version, active)`
- `habit_logs(habit_id, date, done)`
- `audit_log(id, ts, tool, args, result)`: every tool call, for debugging and trust

## 8. Model routing

1. Haiku 5.5 classifies the request (simple or complex) and handles simple ones: add a reminder, list today.
2. Sonnet 5.5 is the default for planning, rescheduling and summarising.
3. Opus 5.5 is used only on explicit escalation.

Prompt caching is applied to the system prompt and tool definitions to keep the cost low.

## 9. Milestones

1. **Core:** project skeleton, systemd unit, SQLite, Discord bot with the allowlist, agent loop.
2. **Calendar:** Google OAuth and the calendar tools.
3. **Reminders:** reminders table, scheduler, Discord delivery, persistence across restarts.
4. **Habits:** identities, habits, daily check-in, never-miss-twice nudges.
5. **Mail (read-only):** Gmail tools, multiple accounts.
6. **Digest:** weekly summary and weekly habit review.
7. **iOS app:** chat, dashboard, EventKit sync for Reminders.
8. **Extras:** second chat channel, mail drafts, backups and monitoring polish.

## 10. Estimated cost

- Hosting: free (own machine; a small electricity cost).
- Discord, Google Calendar API and Tailscale: free.
- Anthropic API: a few euros per month for personal use.
- Apple Developer account: not needed for now (99 $/year if you later want push or TestFlight).
